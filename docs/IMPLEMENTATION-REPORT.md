# Finance implementation report

## Preserved source features

The original FinanceWorkspace component and its relevant dependency closure are retained: dashboard, recurring payments, spending, category budgets, accounts/cards, transaction list/detail, internal/nonspend analysis, TIPS worksheet, receipt reconciliation, bank/card/Hometax/RCMS file imports, splits, category/rule editing and CSV/XLSX/JSON exports. Research-request creation/history, required documents, messages, generated workbook forms and post-purchase evidence screens are also retained and reachable in the menu. This is the original application structure with new monochrome tokens and an independent server transport.

The original deterministic spreadsheet parser uses the original vendored SheetJS 0.20.2 package. Original money/refund/recurring/flow/date-window/invoice/evidence algorithms remain. Empty workspaces now start in the current month and show no-transactions classification wording; existing workspaces open the newest recorded month.

## Actual persistence and server workflows

- All browser data functions use authenticated HTTP endpoints backed by owner-scoped D1 records. Zod validates mutations; owner is derived from ChatGPT platform identity, never request JSON. Duplicate keys are scoped to owner/table.
- D1 migrations are generated by Drizzle (`0000_massive_tag.sql`, `0001_flawless_carnage.sql`). No request-time DDL or production seed records.
- Budgets, custom categories, spending rules, bank/card/invoice metadata, request fields/messages and user settings persist on the server. Original data-function contracts are retained.
- Core ledger updates write only supplied fields through atomic JSON patches, including explicit nulls. Concurrent updates to different fields preserve one another. Deleting a matched invoice or bank transaction clears its reciprocal link in the same database batch.
- Split replacement validates parent ownership and total before an atomic D1 batch. Invalid replacement leaves prior splits intact. Generic endpoints cannot bypass the dedicated split mutation API.
- Parent amount edits and enriched reimports cannot invalidate existing split totals; the user must clear and recreate the split first. Account balances use the latest chronological statement balance and only subsequent movements, so incomplete statement imports do not overwrite a later authoritative balance.
- TIPS refund pairs validate both accounts, source ownership and amount; a unique database index prevents reusing one refund source. Linked source edits/deletes are blocked until unlinked. Invoice matching synchronizes the reciprocal bank reference.
- Receipt bytes and request attachments use authenticated owner-prefixed R2 storage. Blob writes roll back when document metadata persistence fails. Browser URLs do not expose an unprotected bucket or permanent signed public URL.
- Research requests read through the user's real transaction ledger and store only user-created/overridden records. Server-side transitions use the original request/evidence validators; client-provided document and author claims are not trusted.
- Original AI adapter implementations call OpenAI with server-only user credentials/model. Missing credentials, required user guide or business registration number produce setup errors. Job status/failure metadata is stored in D1 and visible in Settings. No model calls were made during verification.
- RCMS registration performs authenticated HTTP calls to a configured user-owned runner. It does not fabricate registered/submitted responses.

## Removed company material

Removed company branding, hardcoded project ID/title/dates/principal, original business-registration number, account suffixes, private landlord/vendor personal-name alias mappings and company examples in comments/placeholders. Project metadata, business number, TIPS guide, merchant aliases and optional companion URL start empty and are entered by the user. No source history, budget snapshots, original request history, financial records, emails, keys or company assets were copied. LocalStorage is used only for the original display preferences (column widths/TIPS toggle), never business records.

Source scan found no original company names, people, account suffixes, business number or source operational URLs in application code. Internal source directory names and conversation-only instructions were removed from the shipped development notes. Source ownership remains private pending license review; third-party notices and SheetJS/font/starter licenses are preserved.

## Remaining integration/release limitations

1. User must configure D1/R2, platform sign-in, server OpenAI key/model and their own project/business number/guide. Paid AI responses, actual bank/company documents and government submissions were deliberately not exercised.
2. RCMS requires a user-owned runner implementing the documented HTTP contract and the compatible companion. This repository includes the HTTP adapter and original registration UI, not the original external browser-automation program or a live government account. End-to-end registration remains unverified.
3. Job status is durable and observable, but execution is request-bound; jobs are not a Cloudflare Queue-backed retry/resume system. Original client-side classification batches still end if the browser closes. Interrupted server requests can retain a running status until reviewed.
4. D1 compatibility queries currently load an owner's entity collection and apply original filters/order/pagination in the Worker. This retains original contracts but should become indexed relational queries for very large ledgers. Imports currently validate up to 2,000 rows per mutation. No large-volume performance claim is made.
5. Whole research-request saves do not yet provide multi-editor revision conflict resolution. The parent verified the empty-workspace browser screens and budget save/reload. Remote migration/credential setup, GitHub publication and live deployment are owned by the parent and are not claimed by this report.
6. Historical research-request and budget snapshots were company records and are intentionally absent. The generic requirement/form catalog is retained, but users must verify its suitability for their own agreement; the service does not provide official regulation updates.
